# NABD — حزمة تطوير Gold Pulse v3.2

تحديث الإصدار 3.2 للمستودع الأصلي `baderfcb232-hue/gold-pulse-ai`، انطلاقًا من commit `fb12ff2` على الفرع `main`. هدفه تحديث خدمة `gold-pulse-ai` نفسها على `https://gold-pulse-ai.onrender.com/`.

يُنشر هذا التحديث عبر الفرع `main` المرتبط بالخدمة القائمة. تُراجع نسخة `/healthz` والواجهة على الرابط الحالي للتحقق من النشر؛ تغيّر الكود على GitHub وحده لا يثبت اكتمال النشر على Render.

أُبقي ملف الدخول `server.js` وأمر التشغيل `node server.js` متوافقين مع الخدمة الحالية. انتقلت وظائف الخادم من Express v2.5 إلى خادم Node 24 المدمج مع تحقق بيانات البروكر وحماية حساب المشغّل؛ لا توجد حزم npm خارجية.

## التحسينات المنفذة

- واجهة عربية تتكيف مع الهاتف، بقائمة سفلية للموبايل وجانبية للشاشات الكبيرة، وستة أقسام: السوق، التوصيات، الصفقات، الأخبار، النتائج، والربط.
- حالة اتصال محسوبة من عمر السعر واتصال المنصة. عند غياب البيانات تظهر الأسعار فارغة والمخاطرة «غير معروفة».
- شارت من شموع البروكر نفسه، لأطر M5 وM15 وH1 وH4، مع متوسط فترة EMA السريع المضبوطة في البوت ومستويات الخطة.
- حساب اتجاه وRSI وATR من شموع مغلقة فقط؛ لا يُستخدم وصف «ذكاء اصطناعي» لتضخيم نتيجة قواعد ثابتة.
- التوصية الرئيسية تأتي من البوت نفسه، بدخول وستوب وهدف أصلي ثابت، مع سجل SQLite يوضح حالة الحفظ وتصدير آخر 200 إشارة إلى CSV. محرك الموقع المنفصل متاح باختيار صريح.
- فصل نتائج التوصيات الافتراضية عن العمليات المؤكدة في MT5. درجة التوافق لا تُعرض كاحتمال نجاح.
- تقويم أخبار USD من MetaTrader، وتوقيت غزة. يمنع محرك الموقع توصيات جديدة عند تعذر التقويم أو تقادمه.
- حاسبة لوت حسب tick size وtick value وحجم اللوت الأدنى وخطوته والهامش والعمولة.
- دخول مشغّل لحماية الرصيد والصفقات والعمليات. رمز ربط MT5 مختلف عن رمز الدخول.
- دليل ربط داخل الموقع، وحالة منفصلة لوصول السعر وحالة البوت، وتنزيل خاص بملفات MT5 بعد دخول المشغّل.
- إدارة اختيارية للصفقات: إيقاف دخول جديد، استئناف، إغلاق صفقات البوت، نقل الستوب لسعر الدخول، وإغلاق جزئي لحساب Hedging. التنفيذ ينتظر تأكيد MT5.
- جسر شبكة يعمل على شارت منفصل. البوت التجاري لا ينفذ WebRequest، وتبقى إدارة صفقاته المحلية مستقلة عن اتصال الموقع.
- أداة اختبار تاريخي لمحرك توصيات الموقع، مع افتراضات تكاليف واضحة، دون نتائج ربحية مختلقة.

## تشغيل محلي

يلزم Node.js 24 أو أحدث. لا توجد مكتبات npm خارجية؛ SQLite جزء من Node.

1. فك الحزمة وافتح المجلد في الطرفية.
2. انسخ `.env.example` إلى `.env`.
3. أنشئ رمزين مختلفين، كل واحد 32 حرفًا أو أكثر. يمكن تشغيل هذا الأمر مرتين، ونسخ كل قيمة إلى متغيرها في `.env`:

```bash
node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
```

4. للتشغيل المحلي غيّر `PUBLIC_BASE_URL` إلى `http://localhost:3000`، ثم شغّل:

```bash
node --env-file=.env server.js
```

5. افتح `http://localhost:3000`. ستظهر «انتظار البيانات» حتى يصل ربط حقيقي. لا تحتاج إلى إدخال بيانات سوق تجريبية لتشغيل الواجهة.

للتطوير والفحص:

```bash
npm test
```


## النشر على خدمة Render الحالية

استعمل **الخدمة القائمة نفسها**، دون إنشاء خدمة أو Blueprint جديد أو تغيير اسم الموقع. معرف الخدمة الظاهر في لوحة المستخدم: `srv-db3br0cs728c73c0jss0`.

| الإعداد | القيمة |
|---|---|
| مستودع GitHub | `baderfcb232-hue/gold-pulse-ai` |
| فرع Render | `main` |
| Root Directory | فارغ، جذر المستودع |
| Runtime | Node 24 |
| Node version | `24.21.0` في `.node-version`؛ المتغير `NODE_VERSION` إن وجد له الأولوية |
| Build command الموصى به | `npm ci --ignore-scripts`؛ `npm install` متوافق أيضًا |
| Start command | `node server.js`، أو `npm start` الذي يشغّله |
| Health check | `/healthz` |
| `PUBLIC_BASE_URL` | `https://gold-pulse-ai.onrender.com` |
| `SIGNAL_SOURCE` | `EA` لخطة البوت نفسه؛ `DASHBOARD` لاختيار المحرك المنفصل صراحةً |
| `MT5_INGEST_TOKEN` | رمز الجسر، 32 حرفًا أو أكثر |
| `DASHBOARD_TOKEN` | رمز مختلف للمشغّل، 32 حرفًا أو أكثر |
| `DATA_DIR` | `.data` للمراقبة المؤقتة؛ مسار قرص دائم للسجل المستمر |
| `PERSISTENT_STORAGE_CONFIRMED` | `false` في الخدمة المجانية؛ `true` فقط بعد التحقق من الحفظ الدائم |

لا حاجة لتغيير `PORT`: Render يحدده تلقائيًا. لا تضع الرموز في الواجهة أو المستودع. غياب الرموز لا يمنع تشغيل الموقع؛ تبقى البيانات فارغة والاستقبال والتحكم محميين حتى ضبطها وربط MT5.

رفع الكود إلى `main` قد يطلق نشرًا تلقائيًا إذا كان مفعّلًا في الخدمة. بعد النشر يجب أن يعيد `/healthz` النسخة `3.2.0`، وأن تُعرض واجهة «GOLD PULSE / 3.2». لا تكفي عبارة Live وحدها لإثبات نشر هذا التعديل.

### الحفظ في الخدمة المجانية

تعمل الواجهة والمراقبة والشارت والحاسبة دون إنشاء موارد مدفوعة. ملفات Render Free مؤقتة؛ قد يُفقد سجل SQLite عند النشر أو إعادة التشغيل أو نوم الخدمة. تظهر هذه الحالة في الربط والنتائج، ويمكن تنزيل CSV قبل إعادة التشغيل.

أوامر إدارة الصفقات من الموقع متوقفة افتراضيًا ما دام الحفظ الدائم غير مؤكد. هذا يحافظ على ترتيب أرقام الأوامر ومنع إعادة إرسالها بعد فقد القاعدة. يبقى البوت في MT5 مستقلًا في إدارة صفقاته المحلية. لا يُفعّل `PERSISTENT_STORAGE_CONFIRMED=true` على مجلد مؤقت.

السجل الدائم يحتاج قرصًا دائمًا على خطة تدعمه، أو تطوير طبقة التخزين لقاعدة خارجية. لم يُنشأ قرص أو مورد مدفوع. المجلد الدائم يجب أن يحتوي قاعدة SQLite وسجلها، وأن يبقى محفوظًا عبر إعادة النشر. استخدم نسخة خادم واحدة؛ عدة نسخ تحتاج قاعدة وجلسات وقائمة أوامر مشتركة.

لنسخة SQLite احتياطية أثناء التشغيل استخدم API Backup المتوافق مع WAL، أو أوقف الخدمة قبل نسخ مجلد البيانات كاملًا. لا تنسخ ملف `nabd.sqlite` وحده أثناء الكتابة.

### توافق مسارات النسخة السابقة

| المسار | سلوك النسخة الجديدة |
|---|---|
| `GET /api/state` | حالة السوق العامة دون الرصيد أو تفاصيل الحساب؛ غياب البيانات صريح |
| `POST /api/update` | مسار متوافق مع استقبال الجسر الجديد، يحتاج Bearer token وصيغة كاملة تشمل الشموع ومواصفات العقد؛ الصيغة القديمة تُرفض بـ426 وتعليمات الترقية |
| `POST /api/risk-settings` | حاسبة محمية للمشغّل؛ تستخدم الدخول والستوب ومواصفات البروكر الحقيقية، ولا تغيّر إعدادات مخاطرة MT5 |
| `POST /api/mt5` | مسار الجسر الحالي لإرسال السعر والشموع والخطة والتقويم وبيانات الحساب الاختيارية |
| `GET /api/account` | الرصيد والصفقات والعمليات والأوامر بعد تسجيل دخول المشغّل |

أزيلت بيانات Yahoo الاحتياطية التي كانت تخلط عقد الذهب الآجل بسعر بروكر MT5، والاتجاهات والسبريد ونسب الثقة والمناطق الثابتة. فشل الأخبار لا يُعرض كغياب للأخبار الخطرة. قسم الأخبار يستعمل تقويم MetaTrader الفعلي مع حالة توفره ووقته.

## تركيب الربط على MT5

### 1. إعداد ملفات المنصة

- انسخ ملفات `mt5/` الأربعة إلى مجلد واحد داخل `MQL5/Experts/NABD/`.
- افتح ملفي `.mq5` في MetaEditor ثم Compile. يجب بقاء ملفي `.mqh` بجانبهما.
- لم يتوفر MetaEditor في بيئة إعداد هذه الحزمة؛ يجب التأكد من نجاح Compile واختبار الربط في منصة MT5 فعلية قبل تشغيل إدارة الحساب.
- تستخدم النسخة التجارية الأصلية حساب JustMarkets. الجسر نفسه لا يفتح صفقات.

### 2. شارت البوت التجاري

أرفق `XAUUSD_Technical_Bot_NABD_v3` على شارت الذهب الذي يديره البوت:

- احتفظ بإعداداتك السابقة. الإعدادات الافتراضية تشمل `InpEnableLiveTrading=false`، وربحًا صغيرًا مستهدفًا قدره 1.00 **بعملة الحساب**، ومخاطرة 0.50%، وحد خسارة يومي 2%، وMagic رقم 26092301.
- اضبط `InpEnableNABDLink=true` لإرسال الحالة محليًا إلى الجسر.
- اترك `InpNABDAllowRemoteControl=false` إذا أردت المراقبة فقط.
- هذه النسخة تنقل خطة البوت الأصلية وحالة الربط وإيقاف الدخول من الموقع؛ لا تغيّر قواعد دخول EMA 50/200 أو إعدادات الربح الصغير الأصلية.
- لا تشغّل نسختين من البوت التجاري للرمز وMagic نفسيهما. استبدل النسخة القديمة عند الانتقال إلى المرتبطة.

### 3. شارت الجسر المنفصل

افتح شارتًا ثانيًا، وأرفق `NABD_Bridge_EA` عليه. الجسر والبوت التجاري يحتاجان إلى **المنصة نفسها والحساب نفسه والرمز نفسه وMagic نفسه**.

| Input | الإعداد |
|---|---|
| `InpSymbol` | اسم رمز الذهب كما يظهر لدى الوسيط، بما فيه أي لاحقة |
| `InpMagicNumber` | Magic البوت التجاري نفسه |
| `InpNABDUrl` | رابط الخدمة بعد نشر الخادم الجديد |
| `InpNABDToken` | قيمة `MT5_INGEST_TOKEN` من إعدادات الخادم |
| `InpNABDRefreshSeconds` | 3 ثوانٍ أو أكثر |
| `InpNABDSendAccount` | `false` للمراقبة العامة؛ `true` لإرسال الرصيد والصفقات للسجل الخاص |
| `InpNABDAllowRemoteControl` | `false` افتراضيًا |
| `InpNABDServerUtcOffsetMinutes` | الكشف الحالي تلقائيًا؛ يمكن ضبط فرق توقيت خادم الوسيط بالدقائق يدويًا |

في MT5: Tools → Options → Expert Advisors → Allow WebRequest for listed URL، وأضف رابط الموقع HTTPS. الرمز في الجسر لا يمنح دخول المشغّل.

حمّل تاريخ M5 وM15 وH1 وH4. يحاول الجسر إرسال آخر 320 شمعة. محرك الموقع المنفصل يحتاج 220 شمعة لكل إطار؛ البوت المحلي يتحقق من تاريخ الفريمات المستخدمة في إعداداته. التعليق على نقص البيانات لا يُستبدل بإشارة مصطنعة.

اضبط ساعة الجهاز على UTC الصحيح ومزامنة الوقت. بيانات شموع MT5 والتقويم تستخدم وقت خادم الوسيط، ويحوّلها الجسر إلى UTC. الإزاحة التلقائية هي إزاحة الخادم **الحالية**؛ قد يحتاج التاريخ الممتد عبر تغير توقيت الصيف إلى تحويل تاريخي مخصص قبل إجراء Backtest. الإزاحة اليدوية لا تعالج تغير DST التاريخي وحدها.

### 4. التحكم الاختياري

لإتاحة إدارة الصفقات من الموقع، بعد فحصها على حساب تجريبي:

- فعّل `InpNABDAllowRemoteControl=true` في البوت التجاري **وفي الجسر**.
- فعّل `InpNABDSendAccount=true` في الجسر.
- إدارة الإغلاق وتعديل الستوب تتطلب أيضًا السماح بالتداول في المنصة وفي البوت. الموقع لا يفعّل إعداد التداول المحلي.
- ادخل الموقع باستخدام `DASHBOARD_TOKEN`، وأكّد كل أمر في نافذته.

إيقاف الدخول لا يوقف إدارة الصفقات القائمة. يستمر البوت في تطبيق فلاتره المحلية بعد الاستئناف، بما فيها إيقاف الطوارئ. نقل الستوب إلى الدخول لا يعوّض العمولة أو السواب.

الأوامر مقيدة بصفقات الرمز وMagic المرتبطين. في حساب Netting يفحص الجسر تاريخ المركز حتى لا يدير مركزًا مختلطًا مع عمليات أخرى. الإغلاق الجزئي متاح لحساب Hedging فقط وبحجم تسمح به حدود الوسيط.

كل أمر تنتهي مهلة إرساله بعد 20 ثانية. «بانتظار MT5» ليس تأكيد تنفيذ. يسجل الجسر رقم الأمر قبل إرساله للوسيط حتى لا تتكرر عملية الإغلاق عند فقد الرد؛ «التأكيد غير مكتمل» يحتاج مراجعة المركز في MT5 قبل إرسال أمر جديد. حالة الإيقاف تحفظ في Global Variables المحلية وتبقى بعد إعادة تشغيل المنصة.

لا تحذف قاعدة البيانات لتصفير النتائج بينما تستخدم سجل أوامر المنصة نفسه: ترتيب أرقام الأوامر جزء من منع التكرار. نقل الخدمة يتطلب الاحتفاظ بالقاعدة وسجل المنصة، أو إعادة تهيئة الربط بإجراء مقصود بعد التحقق من جميع الأوامر والمراكز.

## مصدر التوصية الموحد

الإعداد الافتراضي `SIGNAL_SOURCE=EA`: البوت يكوّن الخطة محليًا، ويكتبها في Global Variables للمنصة، والجسر ينقلها للخادم. الخادم يحفظ الدخول والستوب والهدف الأصليين دون إعادة حسابهما أو إضافة هدف أول وهمي. درجة توافق رقمية غير موجودة في البوت لا تُختلق في الواجهة.

لا يتحول الموقع إلى استراتيجية أخرى تلقائيًا إذا توقفت حالة البوت. وصول السعر وحده لا يكفي: يجب أن تصل أيضًا حالة حديثة من البوت خلال 5 ثوانٍ. عند تفعيل إيقاف الدخول أو الطوارئ، لا تُصدر توصية جديدة. تبقى المتابعة الافتراضية والسجل والعمليات الفعلية منفصلة.

للاطلاع على المحرك السابق بصورة مقصودة اضبط `SIGNAL_SOURCE=DASHBOARD` على الخادم، ثم أعد التشغيل. سجل النتائج يتيح اختيار المصدر حتى لا يجمع أداء استراتيجيتين مختلفتين في نسبة واحدة. خيارات السيطرة على البوت تبقى خاضعة لحالته المحلية حتى عند استخدام محرك الموقع.

في شاشة «الربط» تتحدث خطوات الإعداد من البيانات الفعلية. تنزيل ملفات المنصة من `/api/mt5.zip` يحتاج دخول المشغّل ويجهز الملفات الأربعة الحالية، دون رموز أو أسرار.

## محرك توصيات الموقع الاختياري

`EMA-PULLBACK-1` مستقل عن البوت الأصلي. يستخدم EMA 8/21/200 وRSI 14 وATR 14، توافق M15 وH1، وعدم تعارض H4، ثم ارتداد M5 وكسر الشمعة السابقة مع حدود للسبريد والملاحقة السعرية.

الإعدادات في `engine.mjs` → `defaults`: سبريد أقصى 80 نقطة بروكر، عمر سعر أقصى 20 ثانية، وقف توصيات 30 دقيقة قبل وبعد خبر USD مرتفع الأهمية، صلاحية الإشارة 15 دقيقة، وهدفان 1.5R و2.5R. تحتاج هذه الحدود إلى معايرة واختبار بمواصفات الوسيط، ولا توجد بيانات تثبت ربحية الاستراتيجية.

متابعة خطة البوت تستخدم مستوياتها الأصلية. محرك الموقع عند اختياره يعتمد دخول Ask لشراء BUY وBid لبيع SELL؛ كلا المصدرين يتابعان خروج BUY على Bid وخروج SELL على Ask. الإشارات الافتراضية ليست صفقات منفذة؛ أسعار المتابعة تصل كل عدة ثوانٍ وقد تفوّت حركة بين تحديثين. انتهاء المهلة لا يُحسب كربح أو خسارة وهميين. نتائج الواجهة من آخر 200 إشارة، قبل تكاليف التنفيذ؛ تُعرض العمليات الفعلية في قسم مستقل.

مناطق الطلب والعرض مستخرجة من الشموع وكسر المستويات، وليست إثباتًا لأوامر مؤسسات أو دفتر أوامر مركزي. لا تعرض الحزمة نسب شراء وبيع ثابتة باسم عمق السوق.

## اختبار تاريخي

يختبر `backtest.mjs` استراتيجية الموقع فقط. اختبار البوت الأصلي يتم في MT5 Strategy Tester بدون جسر الشبكة.

زوّد ملف JSON حقيقيًا يحتوي على `symbol` و`broker` و`spec` مثل صيغة الجسر، وعلى `candles` لكل من M5/M15/H1/H4 بترتيب زمني تصاعدي، و`spread_points` و`commission_per_lot` لدورة كاملة و`slippage_points`.

يلزم تقويم تاريخي مكتمل بصيغة:

```json
{"calendar":{"status":"historical_complete","coverage_from":0,"coverage_to":0,"events":[]}}
```

الأصفار في هذا المثال بنية فقط؛ استبدلها بنطاق UTC الفعلي، وأدخل أحداث USD وأهميتها ووقت صدورها. ملف دون تغطية أخبار يرفض الاختبار إلا بتعطيل معلن للفلتر.

```bash
node backtest.mjs broker-dataset.json --output report.json
```

عند اختيار اختبار دون حماية الأخبار صراحة:

```bash
node backtest.mjs broker-dataset.json --without-news-filter --output report.json
```

الاختبار يفترض قيمة tick ثابتة وسبريدًا محددًا، ولا يشمل السواب. يفترض لمس الستوب أولًا إذا لمس السعر الهدف والستوب داخل الشمعة نفسها، ويضيف العمولة والانزلاق. هذه محاكاة OHLC وليست محاكاة كل تيك. لا توجد نتائج Backtest لبيانات سوق حقيقية مرفقة.

## ما تبقى للنشر

التحديث مبني على المستودع الأصلي ومراجع باختبارات الخادم والمنطق والتوافق. يلزم ضبط رمزي الخادم في خدمة Render الأصلية، ثم Compile لملفات MT5 وربط الجسر والتحقق من المصدر الفعلي. يتم ضبط الرموز في Render والمنصة؛ لا توضع كلمات المرور أو المفاتيح في المحادثة أو المستودع.

المراجع الرسمية لإعداد Node والحفظ: [Render Node version](https://render.com/docs/node-version)، [Render Free](https://render.com/docs/free).
